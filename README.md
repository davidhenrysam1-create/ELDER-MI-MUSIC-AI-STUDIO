# Elder Mi Music AI Studio

**Your Sound. Your Culture. Your Studio.**

An Afrobeats-first production platform with three connected workspaces:

| Workspace | Purpose |
| --- | --- |
| **Sam Vocal Studio** | AI-assisted choruses, harmonies, ad-libs, vocal doubles, backing vocals and South-African-inspired choir stacks built from your own recording. |
| **Sam Mix Studio** | Stem import (including ZIP packs), a real mixing console (gain, pan, EQ, compression, sends, width, groups), AI mixing stages you review before applying, measured mix analysis and verified bounces. |
| **Sam Mastering Studio** | Measured loudness/true-peak analysis, seven mastering starting points, a real processing chain, loudness-matched A/B comparison, technical reports and WAV/MP3 delivery. |

This is a working application, not a landing page or a visual prototype: audio is decoded,
processed, measured, stored and exported for real.

---

## 1. What was here before

The repository started as a **Kotlin/Jetpack Compose Android prototype** (`app/src/main/java/com/example/...`).
It could not be built in this environment (no JDK/Android SDK) and much of it was simulated:
random VU values, a synthetic sine "player", hard-coded LUFS numbers and an "export complete"
message with no file. The master brief requires a Next.js web application and explicitly forbids
fake audio results, so the Android prototype was replaced by this web studio. It remains in the
Git history, and the architecture/plan documents are kept in [`plan_app.txt`](./plan_app.txt) and
[`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md).

## 2. Quick start

```bash
npm install
cp .env.example .env.local     # optional: add a Gemini key
npm run dev                    # http://localhost:3000
```

The dev server binds to `0.0.0.0:3000`. Private audio and the project index live in `./.data`
(created automatically, git-ignored).

Production:

```bash
npm run build
npm start
```

> **Deployment note:** `.data` must be a persistent volume. Serverless platforms with an ephemeral
> filesystem will lose audio between requests. For multi-user hosting, replace
> `lib/server/db.ts` + `lib/server/storage.ts` with Postgres/Supabase and object storage; all
> callers use the same repository functions.

### Scripts

| Command | Purpose |
| --- | --- |
| `npm run dev` | Dev server on `0.0.0.0:3000` |
| `npm run build` / `npm start` | Production build and server |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Vitest unit/integration tests (DSP, prompt engine, persistence) |

## 3. Devices: phone, tablet, laptop, desktop

The studio is one responsive web app — no separate mobile build — and it installs as an app:

| Device | How it runs |
| --- | --- |
| **Android phone / tablet** | Open the URL in Chrome → menu → **Install app** (or the in-app "Install" prompt). Launches full-screen with its own icon. |
| **iPhone / iPad** | Open in Safari → **Share** → **Add to Home Screen**. Runs full-screen with the studio icon; the app tells you this on first visit. |
| **Windows / macOS / Linux laptop** | Open in Chrome/Edge → install icon in the address bar, or run it as a normal browser tab. `npm run dev` binds to `0.0.0.0` so other devices on your network can open `http://<your-computer-ip>:3000`. |
| **Desktop workstation** | Full layout up to 1800px+ (the shell widens instead of stretching text). |

Responsive behaviour that is built in:

- Layouts start at **320px** and are phone-first: the sidebar becomes a drawer, the studios gain a
  compact workspace tab bar, and panels only split into columns when there is real room
  (`sm` 640 / `lg` 1024 / `xl` 1280 / `3xl` 1800).
- **Safe areas** — the fixed player, top bar and modals respect notches and the iPhone gesture bar
  (`env(safe-area-inset-*)`, `100dvh`).
- **Touch** — 16px fields (so iOS never zooms on focus), 36px minimum tap targets, larger slider
  thumbs and `touch-action: none` on waveforms so dragging seeks instead of scrolling the page.
- **Mixer** — channels scroll horizontally with snap points; wide tables scroll inside their panel.
- **Modals** — become bottom sheets on phones with a scrolling body, and stay centred on desktop.
- **Print** — a light print stylesheet for the mastering technical report.
- **Offline** — the app shell is cached by a service worker; audio and API calls are never cached.
  Navigating offline shows an honest `/offline` page explaining that the studio server is required.

Icons are generated by `node scripts/generate-icons.mjs` (192/512/maskable/apple/favicon) so the
brand mark can be regenerated without image tooling.

## 4. Using the studio

1. **Create a project** (dashboard → *Create New Project*): name, genre, tempo, key.
2. **Vocal work** — in *Sam Vocal Studio*, upload an instrumental or a lead vocal, choose a tool
   (chorus, harmony, ad-lib, choir, doubling, backing), set intensity/density/layers and the render
   section, then *Generate*. Each result becomes its own lane with play, mute, solo, volume, pan,
   reverb send, width, rename, reorder, re-render and export. Use *Arrangement assistant* to review a
   written section-by-section plan before applying it to the settings.
3. **Mixing** — in *Sam Mix Studio*, drop stems (individually or as one ZIP). Each file becomes a
   channel. Pick a genre starting point, describe the mix, press *Improve My Prompt*, then
   *Apply Mixing Recommendations* to get reviewable stages with concrete channel values. Apply a
   selection, fine-tune the console, *Analyse mix* to measure it, then *Bounce mix*.
4. **Mastering** — in *Sam Mastering Studio*, the latest bounce is preselected. *Analyse source*,
   choose a profile, adjust the targets, *Render master*, compare original vs master with loudness
   matching, then open the *Technical report* and export WAV/MP3.
5. **Everything persists** — projects, audio objects, mixer state, mastering targets, versions,
   jobs and exports are stored server-side. "Save version" snapshots the studio state; restoring is
   reversible.

### Supported audio

- Uploads: WAV, AIFF, FLAC, MP3, OGG, M4A (browser decode) — default limits 80 MB / 12 min.
- Stem packages: `.zip` is unpacked in the browser; non-audio entries are ignored.
- Exports: WAV 16-bit (TPDF dither, optional), WAV 24-bit, WAV 32-bit float, MP3 320 kbps.
- Native **.flp** / **.cpr** projects are detected and explained rather than reconstructed — a guide
  for exporting consolidated stems is built into Sam Mix Studio.

## 5. What is real, what needs configuration

`Settings → Capability matrix` and `/docs` show the same table. Summary:

**Implemented and exercised**

- Browser-side decoding, canvas waveforms from real sample peaks, Range-request streaming, seeking.
- ITU-R BS.1770-4 gated loudness, 4× oversampled true peak, crest factor, loudness range, stereo
  correlation/width, octave-band balance, clipping detection.
- Channel EQ (low shelf 120 Hz, bell 1 kHz, high shelf 8 kHz), native compression, reverb/delay
  sends, per-channel and group faders, mid/side width, mix-bus gain and a true-peak safety limiter.
- Vocal layering with granular pitch shifting, detune, ensemble spread, filtering and reverb.
- Mastering chain: tonal shelves, glue compression, width, saturation, look-ahead limiter with
  post-render true-peak verification and iterative loudness targeting.
- WAV/MP3 encoding, private storage, export history, project versions, atomic JSON persistence.

**Implemented, awaiting a provider/credential**

- *Improve My Prompt* and AI mixing stages use **Gemini** when `GEMINI_API_KEY` is set. Without it,
  a deterministic music-production rule engine runs and the response is labelled
  `local-heuristic` — the UI never claims a model was called.
- **Neural voice transformation** requires a licensed external provider and explicit consent. The
  tool is disabled and explains why; no placeholder audio is produced.

**Deliberately not implemented**

- AI singing synthesis from lyrics, automated reference-track matching, native DAW project
  reconstruction, multi-user accounts/cloud storage. These are listed as planned/unsupported rather
  than faked.

## 5b. AI music generation (beats, songs, vocal hooks)

The studio can now **create new audio** — a beat, an instrumental, a full song or a vocal hook — using
hosted models. It is deliberately behind four honest gates:

| Gate | Behaviour |
| --- | --- |
| Provider key | Each provider is listed as **Real** only when its key is present; otherwise **Awaiting configuration**, with the exact variable name shown. |
| Paid generation switch | Off by default. While off, `POST /api/generate` refuses every request with **403** and no vendor is contacted. |
| Spend cap | A request whose estimate would push tracked spend past `spendCapUsd` is refused with **402**. Tracked spend is the studio's estimate from configurable per-second prices — the vendor invoice is authoritative. |
| Provenance | Every generated file is stored as a normal asset with `providerId`, `modelId`, `prompt`, `licence`, `costUsd` and `jobId` recorded on it. |

Supported adapters (all optional, all billed by the vendor to your own account):

| Provider | Kinds | Max length | Key |
| --- | --- | --- | --- |
| Google Lyria 2 (Vertex AI) | beat, instrumental | 30 s | `GOOGLE_API_KEY` **or** `GOOGLE_VERTEX_ACCESS_TOKEN` + `GOOGLE_VERTEX_PROJECT` |
| Stability Stable Audio 2 | beat, instrumental | 190 s | `STABILITY_API_KEY` |
| ElevenLabs Music | song, vocals | 300 s | `ELEVENLABS_API_KEY` |
| MusicGen (Replicate) | beat, instrumental | 120 s | `REPLICATE_API_TOKEN` |

**No model ships with this repository.** There is no local Mersenne/Torch-style model to download: the
studio is a browser + Node application, so "AI generation" always means a hosted provider you supply a
key for. Mixing, mastering, analysis, vocal layering and export are untouched by this and work fully
offline.

Where it appears: **Sam Mix Studio** (Generate panel above the mixing stages) and **Sam Vocal Studio**
(Generate panel in the vocal tools column); the catalogue, spend cap and paid-generation switch live in
**Settings → AI music generation**. The existing `GEMINI_API_KEY` integration is unchanged and still
only drives prompt improvement and mixing suggestions.

How to try it safely:

1. Add one provider key above to `.env.local` and restart (`npm run dev`).
2. Settings → *Allow paid generation* on, cap at something small (e.g. `1`).
3. In Sam Mix or Sam Vocal, pick the provider, write a brief, watch the live estimate, press
   **Generate audio**.
4. The job list shows the provider's own status text. Long-running providers (Replicate) are polled;
   you can cancel, and a cancelled or failed job is never charged.

## 5c. Accounts, sign-in and sharing

The studio is now **multi-account on your own server**. Each account sees only its own projects,
audio, exports, voice profiles and share links.

### Signing in

| Screen | What it does |
| --- | --- |
| `/signup` | Name, email, password (8+ chars) **and your roles** — artist, producer, engineer (beat maker), promoter, or several at once. The **first** account becomes the studio owner and adopts anything saved before accounts existed, so upgrading loses nothing. |
| `/login` | Email + password, with "show password" and a return path (`?next=`). Shows **Continue with Google** once Google is configured, and says "awaiting configuration" until then. |
| `/welcome` | The role picker, for accounts that arrive without roles (Google sign-in cannot ask). |
| `/account` | Change display name, roles, public handle, bio and AudioMack / Instagram / Facebook links; change password (signs every device out); see active sessions; verification status; close the account. |
| `/u/<handle>` | Your **public page**: name, roles, bio and social links — never your email. No sign-in needed to view it. |
| `/admin` | The admin console (see below). Appears in the navigation only for the admin account. |
| `/admin-bootstrap` | One-time admin sign-in while Google is not configured. |

### Roles and dashboards

Roles are stored on the account (`roles: ["artist", "producer", …]`) and mapped to screens in one file,
`lib/roles.ts`, so the navigation and the API cannot drift apart:

| Role | Gets |
| --- | --- |
| **Artist** | Sam Vocal Studio, publishing/promotion tools, shares. |
| **Producer / beat maker** | The whole studio: vocal, mix, mastering, beats for sampling, shares. |
| **Engineer** | Mixing and mastering plus vocal cleanup; the full three studios. |
| **Promoter** | Publishing and promotion surfaces, shares. No processing tools. |

Holding several roles combines them ("Artist & Producer"). A screen a role cannot use is hidden from the
navigation *and* refused by the server — hiding a link is convenience, not the security boundary. The
admin bypasses the filter and sees everything.

### The admin console

The admin is always the address in `ADMIN_EMAIL`; the right is recomputed on every request rather than
stored, so nobody can promote themselves. `/admin` lists **every registered account** with its roles,
sign-in method, verification state, project/file/storage counts and live share links, and lets the admin:

- set roles (which changes that account's dashboards),
- mark an address verified (the manual fallback while no mail provider exists),
- suspend — which blocks sign-in **and** ends that account's sessions immediately,
- delete an account together with every project, audio file, export and share link it owns.

The admin account itself cannot be suspended or deleted, so the studio cannot lock itself out.

**Getting in as admin:** sign in with Google using the `ADMIN_EMAIL` address. While Google is not
configured, start the app and read the one-time bootstrap code printed in the terminal, then enter it at
`/admin-bootstrap` (single use, 24 hours; set `ADMIN_BOOTSTRAP_CODE` to choose your own). **No admin
password is stored in this repository** — if a password was ever shared in chat, change it wherever it is
used.

How it is stored: passwords are salted **scrypt** hashes (`scrypt$N$r$p$salt$hash`) in `db.json`;
never plaintext, never sent to the browser. Sessions are a random 256-bit token in an `HttpOnly`,
`SameSite=Lax` cookie; the database keeps only its SHA-256, so a copy of the database cannot be
replayed as a login. Sessions last 30 days and are listed by device type — no IP addresses are stored.

Honest gaps, stated in the UI too:

- **No password-reset email** is sent, even with an email provider configured. A forgotten password is
  reset by the person running the server.
- **Email verification links** are issued and expire after 24 hours, but posting them needs
  `RESEND_API_KEY` + `EMAIL_FROM`. Until then the account page says *"no email was sent"* and the admin
  verifies accounts by hand.
- **Continue with Google** is code-complete but visibly off until `GOOGLE_CLIENT_ID` and
  `GOOGLE_CLIENT_SECRET` exist.
- **Publishing, follows, likes and downloads on public pages** are planned, not built: a profile page
  exists, its music shelf says so, and finished songs travel as share links today.
- **No email change** yet.

`ALLOW_SIGNUP=false` closes new accounts; the first account can still be created, and existing accounts
keep working.

### Sharing with friends

`/shares` (or **Share this project** on the dashboard) creates a **read-only listening link** for one
project:

- **No account needed** — `/s/<token>` opens a clean page with project name, your display name,
  genre, tempo, key, a player for every channel on the mixer, and an optional download button.
- **Only channel audio is exposed.** Files stored in the project but not placed on the mixer are never
  served, and mixer settings, mastering chain, versions and other projects are not visible.
- **You decide the terms** per link: listen-only or allow downloads; expires in 24 hours / 7 / 30 / 90
  days or never; optional 4–12 character passcode (stored as a scrypt hash and remembered per browser).
- **Revoke instantly.** Revoking or expiry is enforced on the server for every audio request, not just
  the page.
- **Tokens are hashed at rest**, so the full link is shown **once**, at creation. Lost it? Revoke and
  create another — the UI says this plainly instead of implying it can be recovered.
- **Minimal counters**: opens and downloads per link, plus last opened. No IP addresses, user agents or
  tracking pixels.

Limits worth knowing: a link only works while this studio server is reachable, so friends outside your
network need the app hosted or tunnelled first. Sharing is per project, not per file; export history
still holds finished files, and the owner can hand them over directly.

## 6. Configuration

Copy `.env.example` to `.env.local`:

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Optional. Enables Gemini prompt improvement and mixing stages. Read server-side only. |
| `GEMINI_MODEL` | Optional, default `gemini-2.5-flash`. |
| `DATA_DIR` | Optional private data directory (default `./.data`). |
| `ADMIN_EMAIL` | **Required for admin access.** The one address that always has admin rights. Leave it empty and nobody can open `/admin`. |
| `ADMIN_BOOTSTRAP_CODE` | Optional. Fixed one-time admin code while Google is unconfigured; random and printed to the log if unset. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Optional. Turns on **Continue with Google**. Add `/api/auth/google/callback` as an authorised redirect URI. |
| `GOOGLE_REDIRECT_URI` | Optional. Pins the redirect URI when it differs from `NEXT_PUBLIC_SITE_URL`. |
| `RESEND_API_KEY`, `EMAIL_FROM` | Optional. The only way verification emails are actually sent. Without them nothing is mailed and the UI says so. |
| `ALLOW_SIGNUP` | Optional, default `true`. Set to `false` to close public sign-up. |
| `MAX_UPLOAD_MB`, `MAX_DURATION_SEC` | Default upload limits; editable in Settings. |
| `VOICE_CONVERSION_API_URL` | Reserved for a licensed voice-conversion adapter. |
| `GOOGLE_API_KEY` / `GOOGLE_VERTEX_ACCESS_TOKEN` + `GOOGLE_VERTEX_PROJECT` | Optional. Enables Lyria 2 beat/instrumental generation. |
| `STABILITY_API_KEY` | Optional. Enables Stable Audio 2 beat/instrumental generation. |
| `ELEVENLABS_API_KEY` | Optional. Enables ElevenLabs Music (songs and vocal hooks). |
| `REPLICATE_API_TOKEN` | Optional. Enables MusicGen on Replicate (async, polled). |
| `SPEND_CAP_USD` | Optional, default `5`. Hard ceiling on tracked generation spend. |
| `*_USD_PER_SEC` | Optional cost overrides: `LYRIA_`, `STABLE_AUDIO_`, `ELEVENLABS_`, `REPLICATE_MUSICGEN_`. |
| `STUDIO_PASSWORD`, `STUDIO_USER` | Optional HTTP Basic auth in front of the whole studio (an extra door before accounts). |
| `ALLOW_SIGNUP` | Optional, default `true`. Set to `false` to close new accounts; the first account can still be created. |

Secrets never reach the browser: API routes read them and return only results.

## 7. Architecture

```
app/                     Next.js App Router pages + API route handlers
  page.tsx               Dashboard
  vocal|mix|mastering/   The three studios
  projects|voice-profiles|exports|settings|docs/
  api/                   projects, assets (upload/stream), exports, jobs,
                         prompt improvement, mixing recommendations, settings,
                         providers, generate (+ /generate/[id])
components/              Shell, audio widgets (waveform, player, upload), studio panels
lib/
  audio/                 DSP: analysis, pitch, render, WAV/MP3, peaks, arrangement
  routes.ts              public-route rules shared by the shell and the provider
  client/                Studio provider, API client, audio cache, mixdown, ZIP, export
  server/                JSON store, repository, storage, prompt engine, validation
    auth.ts              accounts, scrypt hashing, sessions, ownership guard
    shares.ts            read-only share links (hashed tokens, expiry, passcode)
    providers/           one adapter per music-generation vendor + registry
    generation.ts        job orchestration, budget gates, provenance, spend ledger
  types.ts, projects.ts  Domain model and defaults
tests/                   Vitest suites (DSP, prompt engine, persistence, migration)
```

- **Rendering happens in the browser** (`OfflineAudioContext` + in-house JS post-chain), so uploaded
  audio is never sent to a third party and long renders don't block the server. Job lifecycles are
  recorded server-side so status survives a reload.
- **Analysis is computed from samples** in `lib/audio/analysis.ts`; no value is pre-filled.
- **Writes are atomic** (temp file + rename) and serialised; every mutation is persisted.
- Design system: deep midnight surfaces, translucent glass panels, gradient display typography,
  neon accents, keyboard-accessible controls and `prefers-reduced-motion` support.

## 8. Security & privacy

- Private audio is stored outside `public/` and served only through `/api/assets/:id/audio`, which
  requires the owning project id and supports ranges.
- Uploads are validated by extension, size and duration on the server as well as in the browser.
- Original files are never overwritten; every generated layer, bounce and master is a new object.
- Deleting a project removes its audio files and exports. Settings → *Delete all studio data* wipes
  everything.
- Voice profiles require explicit consent (name + confirmation) before they can be created.
- No audio leaves the studio server for analysis, mixing or mastering; Gemini receives **text prompts
  only**, and only if configured.
- Music generation is the one outbound path for audio: your **text brief** is sent to the provider you
  chose, and the rendered file is downloaded into private storage. Nothing is uploaded to a provider
  unless you press *Generate audio* with paid generation enabled.

Every page and API route requires a signed-in account. `middleware.ts` only checks that a session
cookie exists (the edge runtime cannot read the JSON store); each request then validates the session,
expiry and ownership in `lib/server/auth.ts` before touching data, so a forged cookie gets a `401`. The
optional `STUDIO_PASSWORD` Basic-auth gate still sits in front of everything as a second door.

For a public deployment also put the app behind HTTPS (the session cookie is marked `Secure` in
production), keep `ALLOW_SIGNUP=false` if it is just you, and back up `.data/`. The storage layer is
still single-node JSON + files; swapping `lib/server/db.ts` for Postgres is the path to horizontal
scaling.

## 9. Testing

```bash
npm test          # 232 tests across 16 files
npm run typecheck
npm run build
```

Covered (`tests/`):

- API contracts: project validation, upload rejection for native DAW files and oversized audio,
  channel-role guessing, version restore checkpoints, export measurement coercion, settings clamps,
  consent-gated voice profiles, labelled AI fallbacks.
- Client pages: every studio and supporting page renders with and without a project, the DAW guide
  opens, a genre preset writes into the project, a mastering profile loads its controls, and the
  voice-transformation tool reports that it needs configuration instead of producing audio.
- UI kit: icons, gradient headings, segmented control behaviour, progress semantics, and a guard
  that fails if a Tailwind opacity step that does not compile (e.g. `border-white/8`) sneaks in.
- Loudness: a 1 kHz, −23 dBFS stereo tone measures ≈ −23 LUFS (EBU-style reference).
- True peak never reports below the sample peak and catches inter-sample overshoot.
- Limiter output respects its ceiling; width control collapses to mono; saturation is stable.
- WAV header round-trip for 16/24-bit PCM and 32-bit float.
- Pitch shift preserves duration and shifts pitch by the expected octave ratio.
- Prompt engine: labelled local fallback, no fabricated claims, bounded recommended settings,
  API-level rejection of empty briefs.
- Persistence: create/patch/reload, atomic JSON, asset file deletion, version save/restore, export
  records, legacy schema migration, purge, file-name sanitisation.
- Helpers: arrangement plans, DAW/MIDI import guardrails, time/byte/level formatting, export file
  naming, preset and prompt-seed integrity.
- PWA: manifest identity, scope, installable icon sizes/purpose, studio shortcuts, service-worker
  rules (no API/audio caching), the offline page, and the install prompt on Android/desktop plus the
  iOS "Add to Home Screen" explanation.
- Responsiveness: shell rendering at any width, active-workspace semantics, the compact mobile tab
  bar, and stylesheet guards for safe areas, `dvh`, 16px fields, coarse-pointer targets and print.
- Roles: the role → studio/route map, that a missing role means no access rather than full access,
  that the admin bypasses every gate, and that the navigation hides what a role cannot open while a
  typed URL gets an explanation instead of the tools.
- Admin and identity: the admin address cannot be claimed or signed into with a password, only
  `ADMIN_EMAIL` is admin, the admin cannot suspend itself, suspending ends the account's sessions and
  refuses sign-in, the bootstrap code is single-use and refused once Google is configured, and the
  admin console refuses non-admins (403) and anonymous callers (401).
- Public profiles: only the holder's handle resolves, emails never appear in the payload, and a
  suspended profile disappears.
- Google and verification: first sign-in creates a verified account, repeat sign-ins link instead of
  duplicating, an existing password account is linked, suspended accounts are refused, verification
  tokens are stored only as a hash, expire, and work once.

## 10. Limitations & roadmap

- Vocal layers are DSP arrangements of your recording; they are **not** synthetic singing. The
  granular pitch engine is intended for harmony/double/choir layering and shows artefacts on extreme
  shifts.
- Analysis/render time scales with length; on low-power devices trim the render section.
- MP3 encoding supports 32/44.1/48 kHz (lamejs limitation) — the UI explains this instead of failing
  silently.
- Mobile limits: rendering happens on the device, so a long mix on an older phone takes noticeably
  longer than on a laptop. Trim the render section in Sam Vocal Studio and bounce in stages.
- iOS: Web Audio needs a user gesture — press play once before expecting monitoring. Background
  downloads can pause when Safari suspends the tab.
- Planned: multi-user auth, object storage, job queue, neural voice conversion adapter, stem
  separation, reference-target mastering, native app wrappers.
